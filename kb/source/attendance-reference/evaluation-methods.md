# Evaluation methods

**Framework:** Users → Tasks → Universal Design principles → Evaluation → Problems → Redesign → Re-evaluation.
Traditional question: "Can a normal student use it easily?" Universal Design question: "Can users of different ages, abilities, languages, digital literacy, devices and environments use it effectively?"

## A. Heuristic evaluation
Evaluator checks the UI against principles. Table form: Is status visible? Is feedback provided? Can users recover from errors? Is information understandable (text+icons+charts)? Is the interface consistent?

## B. Diverse-user testing
Test not just tech-savvy users: the three roles plus elderly users, visual impairment, motor impairment, bright-light use, low digital literacy, slow internet. Give everyone the same task; observe: can they find it, how long, errors, do they understand the value and the alert.

## C. Cognitive walkthrough
Step through a task from the user's view. At every step ask: Will the user know what to do? Will they notice the correct control? Will they understand the feedback? Good for first-time users.

## D. Accessibility checklist (Yes/No)
Sufficient colour contrast; info not by colour alone; text can be enlarged; keyboard navigation; buttons adequately sized; clear error messages; consistent navigation; alt text for important icons/visuals; accessible forms; clear labels.

## E. Task success metrics
Per role task measure: completion rate, time taken, number of errors, number of interactions/clicks, understanding, satisfaction (also: can they correct an error, do they know the action succeeded).
Original tasks: Faculty "record attendance for today's HCI lecture and submit"; Student "find attendance % in Database Systems and decide shortage"; Admin "identify subjects below threshold and generate a report".

## F. Intended outcome chain
Increased usability → higher accessibility → reduced errors → greater satisfaction → compliance readiness. Use results to **modify the interface**.
