# HMI principles applied

| Principle | Meaning | Attendance example |
|-----------|---------|--------------------|
| Visibility of system status | User never guesses whether something happened | Live counts "52 Present / 7 Absent / 2 Late" |
| Recognition rather than recall | Show, don't make users remember | Today's Schedule pre-fills subject, class, time, headcount; student sees subject-wise % directly |
| Error prevention | Make the wrong thing hard | Review & Confirm → Confirm & Submit; "Are you sure?" Yes, Submit / Cancel |
| Feedback | Immediate confirmation of actions | "Attendance Submitted Successfully" + check indicator |
| Consistency | Same concept looks the same everywhere | Present/Absent/Late/Excused, percentage, alerts use one visual language |
| Error recovery | Mistakes are fixable | Review & Correct before final submit |

Infographic also lists: flexibility & efficiency (multiple ways to do a task) and accessibility (readable text, contrast, icons). Status colours legend: Present green, Absent red, Late amber, Excused grey/blue, always paired with text.
