# Goal-Directed Design process

| # | Phase | What happens | Expected output |
|---|-------|--------------|-----------------|
| 1 | Research | Study how the current process works; observe pain points | Interviews, observations, questionnaires, existing-system study |
| 2 | Modeling | Turn research into personas and user models (goals, behaviours, frustrations, tech use) | Personas, user goals, behavioural patterns |
| 3 | Requirements Definition | Convert goals into functional + interaction requirements | Requirements, task analysis, scenarios, use cases |
| 4 | Framework Definition | Design the interaction structure: navigation, dashboard structure, workflow, information hierarchy, feedback, error handling, screen relationships | Information architecture, task flow, navigation map, wireframes |
| 5 | Refinement | Detailed interface design applying HMI principles (visibility, feedback, consistency, affordance, error prevention, recognition over recall, accessibility) | High-fidelity + interactive prototype |
| 6 | Validation | Usability testing with representative users on real tasks; find problems; refine | Test plan, results, observations, design improvements |
| 7 | Final Design / Implementation | Final interactive prototype/application based on validated decisions; show effort reduced and visibility improved | Final prototype + design documentation |

Key rule: **one interface per persona, not one generic interface.** Each role gets an interface shaped by its goal.
Source order in the original: Research → Modeling → Requirements → Framework → Refinement → Validation → Final.
