<task id="10-01-02">
<name>Configure OKLCH tokens in globals.css (light & dark)</name>
<instruction>
Update `frontend/app/globals.css`:
1. Define `@theme` with fixed 4px spacing (`--spacing: 4px`), 12px card radius (`--radius-card`), 8px control radius (`--radius-control`), and Inter font tokens.
2. In `:root`, define the light mode OKLCH tokens:
   - `page`, `surface`, `panel` (zinc foundation)
   - `ink`, `muted` (text)
   - `border-ui` (>= 3:1), `border-card`
   - `accent` (indigo/violet), `destructive` (crimson)
   - Status tokens (`fg` and `bg`) for draft, pending, approved, open, ongoing, completed, cancelled, full, returned, todo, doing, done, overdue, registered, waitlisted, clash, lowreg.
3. In `[data-theme="dark"], .dark`, define corresponding dark mode OKLCH tokens.
4. Keep the `@media (prefers-reduced-motion: reduce)` reset and print styles.
</instruction>
<verification>
Inspect `frontend/app/globals.css` to confirm all light and dark tokens are declared with valid OKLCH coordinates.
</verification>
</task>

<task id="10-01-03">
<name>Upgrade tests/contrast.test.ts for light and dark themes</name>
<instruction>
Update `frontend/tests/contrast.test.ts` to:
1. Parse both `:root` and `[data-theme="dark"], .dark` blocks from `app/globals.css`.
2. Convert OKLCH coordinates to standard linear sRGB luminance ($Y$) and calculate contrast ratio $(L_1 + 0.05) / (L_2 + 0.05)$.
3. Assert that all text pairs, UI border pairs (>= 3:1), and status badge fg/bg pairs satisfy WCAG 2.2 AA in BOTH light and dark themes.
</instruction>
<verification>
Run `cd frontend && npx vitest run tests/contrast.test.ts` and ensure all assertions pass.
</verification>
</task>
