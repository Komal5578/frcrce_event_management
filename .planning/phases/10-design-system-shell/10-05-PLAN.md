<tasks>
<task id="10-05-01">
<name>Configure API proxy rewrites in next.config.ts</name>
<instruction>
Update `frontend/next.config.ts`:
1. Remove all remnants of `@opennextjs/cloudflare`.
2. Add `rewrites()` config mapping `/api/:path*` to `${process.env.API_URL || "http://127.0.0.1:8000"}/:path*`.
3. This ensures session cookies are set first-party without cross-origin issues or manual CORS configuration.
</instruction>
<verification>
Run `cd frontend && npm run build` (or `npm run typecheck`) to verify `next.config.ts` passes compilation.
</verification>
</task>

<task id="10-05-02">
<name>Setup openapi-typescript & generate client types</name>
<instruction>
1. Add `openapi-typescript` to `devDependencies` in `frontend/package.json`.
2. Add npm script `"gen:api": "openapi-typescript ${API_URL:-http://127.0.0.1:8000}/openapi.json -o lib/api-types.ts"`.
3. Provide a baseline `frontend/lib/api-types.ts` representing the FastAPI endpoints documented in Phase 9 research so typing is immediately available.
</instruction>
<verification>
Verify `frontend/lib/api-types.ts` exports standard OpenAPI path definitions and schemas.
</verification>
</task>

<task id="10-05-03">
<name>Build isomorphic typed client in lib/api.ts</name>
<instruction>
Create `frontend/lib/api.ts`:
1. Provide `apiClient<T>(endpoint: string, options?: RequestInit): Promise<T>` helper.
2. In Server Components, use `next/headers` `cookies()` to forward the session cookie to `/api/*`.
3. On non-2xx responses, parse JSON body and map known error codes (`VENUE_CLASH`, `EVENT_FULL`, `RESOURCE_SHORT`, `BAD_STATE`, `NOT_ALLOWED`) into a structured `ApiError` class with human-friendly messages (`dom-status-vocabulary`, `dom-domain-model`).
</instruction>
<verification>
Run `cd frontend && npm run typecheck` to confirm `lib/api.ts` compiles cleanly.
</verification>
</task>

<task id="10-05-04">
<name>Redesign login page with modern campus SaaS styling & demo detection</name>
<instruction>
Update `frontend/app/login/page.tsx` and its components:
1. Apply the modern campus SaaS visual direction:
   - Centered card with subtle elevation and border.
   - Professional typography and brand header.
   - Clean email/password inputs with 44px hit targets and visible error states.
2. Query backend `/api/auth/demo-status` (or read env state):
   - If demo login is enabled (`DEMO_LOGIN=true`), show one-click demo login buttons for Coordinator, Student, and Admin.
   - If disabled, hide demo buttons cleanly.
3. Include A-/A/A+ text sizing control and theme toggle in the header.
</instruction>
<verification>
Run `cd frontend && npm run typecheck` to verify the login page compiles cleanly.
</verification>
</task>
</tasks>
