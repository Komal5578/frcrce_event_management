Create `docs/research/check-kit.mjs` (ESM, imports only from `node:fs`, run from the repo root, roughly 60-80 lines, ponytail: no config, no flags). It collects error strings and, at the end, prints them to stderr and exits 1, or prints `ok: kit checks passed` with the question count and exits 0. Checks, in this order:

1. For `docs/research/interview-guide.md` and `docs/research/questionnaire.md`: each must contain level-2 headings matching `^## ` followed by text containing Coordinator, Student and Admin (one check per role). Question lines are bullet lines matching `^[-* ]*(QN?-[CSA]\d{2})\.` (optional `- ` bullet prefix, then the id; Probes and Options sub-bullets do not match); the interview file ids must start `Q-` and the questionnaire ids `QN-`. Each question line must end with a tag list matching `\[P(\d+)(, ?P(\d+))*\]\s*$`; every tag must be in 1..10; ids must be unique within a file. Build a map from each P id to the set of question ids carrying it, split by file. Also track the section: the role of the current question is the most recent level-2 heading containing Coordinator, Student or Admin (equivalently the role letter in the id; use the heading).
2. The union of tags must contain P1 through P10, one error per uncovered id. Per-section coverage: in EACH of the two instruments and EACH role section (Coordinator, Student, Admin), P3, P4, P7 and P8 must each be carried by at least one question; one error per missing (file, role, P id), about 6 lines of code (a loop over a role-to-tag-set map). The interview guide must contain at least one `Probes:` line (substring match).
3. `docs/research/question-trace.md`: for each P1..P10 take the table row whose first cell is exactly that id in the Coverage matrix (the last such row in the file); collect all question ids in the row with a global regex and compare as sets with the ids derived from the tags in step 1; report a row missing or a mismatch per P id. Tags win.
4. Personas: each of `persona-template.md`, `persona-coordinator.md`, `persona-student.md`, `persona-admin.md` in `docs/personas/` exists; each file has a line exactly `confidence: assumed` and matches `assumed, pending research` case-insensitively; `kb/domain/personas.md` also matches the label and still has `id: dom-personas`.
5. `docs/research/results-placeholder.md` contains `evidence` and `only the team` (case-insensitive).

IMPORTANT (self-invalidating greps): the script file lives under `docs/research/`, which the repo-wide tripwire greps scan. Keep the literal words attendance, shortage, quote, findings, participant, respondent and percent signs out of the script text and its messages; the attendance/tripwire/evidence-claim checks are done by the shell greps in Task 2 with `--include='*.md'`, not inside this script. Run it with `node docs/research/check-kit.mjs`; if it reports errors caused by the instruments or personas, fix the offending Markdown file (smallest edit) rather than loosening the script. The script is the single runnable check for non-trivial logic; do not add a test framework. Do not commit (D-05).
  </action>
