<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> server action | public POST endpoint; ids, reason text and form fields are untrusted |
| server action -> lib/domain | actor from the admin session only; domain re-checks role |
| UI clash check -> decision | UI result is advisory; server recomputes and the DB triggers are final |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-31 | Elevation of privilege | approve/return/catalog actions | mitigate | `requireRole("admin")` in every action and page; domain requireActorRole(admin); tests with coordinator/student mocks get NOT_ALLOWED text |
| T-04-32 | Tampering | approving a conflicting event via a forged request | mitigate | approveAction recomputes the clash check server-side; DB triggers (RESOURCE_SHORT, VENUE_CLASH) remain the guarantee |
| T-04-33 | Tampering | catalog form values | mitigate | `_lib/parse.ts` and the domain validate name length, whole numbers, reserved quantity; bound parameters only |
| T-04-34 | Information disclosure | raw DB errors / registrant data | mitigate | only DomainError.message or the generic sentence; admin pages show counts and coordinator names, not registrant names |
| T-04-35 | Tampering (XSS) | titles, department, return reason | mitigate | React escaping; no dangerouslySetInnerHTML; the reason is echoed as text children in ConfirmDialog |
| T-04-36 | Repudiation | approve/return without trace | accept | no audit log in scope (adr-004-scope); return_reason and status are stored on the event |
| T-04-SC | Tampering | npm installs | accept | no package installed; AGENTS.md forbids new dependencies |
</threat_model>
