<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> server actions | untrusted email, password, role field |
| server action -> Supabase Auth | credentials leave the server only here |
| client bundle | must not contain DEMO_PASSWORD |
| cookie -> proxy/layout | session claims drive role guards |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-15 | Information disclosure | DEMO_PASSWORD | mitigate | Read only in app/login/actions.ts server action, no NEXT_PUBLIC_ prefix, grep test + build-output grep |
| T-03-16 | Elevation of privilege | demoLogin role field | mitigate | parseRole whitelist; email from fixed map, never from the request |
| T-03-17 | Tampering | open redirect after login | mitigate | redirect only to homeFor(role) fixed paths; no next param read; tested by grep |
| T-03-18 | Elevation of privilege | server-side route access by wrong role | mitigate | requireRole in each group layout reads profiles.role by claims.sub (getClaims, never getSession); RLS remains the real boundary |
| T-03-19 | Spoofing | demo buttons in a real deployment | mitigate | server-side isDemoEnabled() === 'true' check inside the action, not just hidden buttons |
| T-03-20 | Spoofing | brute force on sign-in | accept | Supabase Auth rate limits; demo-only system, no real data (ASVS L1) |
| T-03-21 | Information disclosure | auth error detail | mitigate | single generic wrong-credentials message, no user enumeration, no codes shown |
</threat_model>
